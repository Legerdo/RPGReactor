# RPG Reactor 0.99.2 (in development)

Work since 0.99.1. The short version is in the [root changelog](../../changelog/0.99.2.md). Runtime **20261024.3**.

### Changed

- Database vehicle placements on the map: `EventManager.vehicleStartOf`/`vehicleLabel`/`vehicleFootprint` (Length = the model's longest side along the start direction, width from the cached GLB extent, 1×1 for a 2D vehicle, centred), `getVehicleAt`, `canPlaceVehicle`, `moveVehicleStart` and `saveVehicleStarts` (writes `ReactorVehicles.json` on the drop and carries the vehicles into the Database window's Cancel snapshot). The 2D pointer-down takes hold of a placement and `updateDrag`/`finishDragging` move and save it; `MapEditor3D.dragEventTo` does the same; undo snapshots carry `vehicles`. The Events list gains a **Vehicles (Database)** section (`.event-list-vehicle`). Tests `vehicles-starting-position`, `map-editor-3d-events`.
- `DatabaseVehicleEditor` starting positions: each row is a grid (`1.6em | 1fr | 92px | 80px`, 30 px high) with its number always shown; the first row's button is Delete like the rest: with copies, the first copy's place and direction move into the record and its number stays retired (`copyCount`); alone, it clears to unplaced. Test `vehicles-equipment-ui`.
- Motion library on any rigged humanoid: `attachLibraryMotions` attaches every `POSES` motion as an empty clip (filled on first play), not only the six movement states; a clip rule's `library: "<id>"` plays it (`rule.clip` = `LIBRARY_CLIP_PREFIX + id`); `libraryMotionRules` skips motions without a state. Database › 3D Models: the clip card lists a Motion library group; a Motion library row adds the builder's battle `SLOTS` as library rules (`addLibraryBattleSet`). Demo Fleagus gets the set. Runtime **20261024.3**. Test `character-3d-motion-library`.
- `DatabaseActionSequenceEditor`: `updateReferences` draws each reference as a `.rr-sequence-reference` button (name, type, id, slot); `previewAs`/`previewAsChoice`/`previewingAs` set the sample action (skills, items), the held weapon and the Attack skill (weapons) or the user (actors, enemies), keeping the cast selects in step; the cast summary names the sample action; the Show Animation step's Action source is labelled "Each Action’s Own" and lists each using record's animation (`data-sequence-action-animations`). Four new strings in all 17 locales. Test `action-sequence-editing`.
- `.database-nav-section` takes the `.lit-section-header` look (3px `--color-accent` strip, `--color-bg-toolbar` band, `--color-text`); `.database-nav-item` padding 7px to 5px. The sidebar's content is 834 px against 895 px of room in a 1001 px tall Database window (1080p with a taskbar; it was 896 against 895, one pixel of scroll), measured in the editor's own window in the dark and light themes.

### Fixed

- `EventEditor._sizeModel` falls back to the event's vehicle model (`RRVehicles.modelOf`) when its first page shows no picture, as `previewModelRaw` does; `refreshAutoSize` turns it by the model file's `vehicle.forward` (`EventEditor.vehicleFront`, the runtime's `forwardOf` rule), so the Demo bike measures 1×5 facing down, not 5×1. `EventManager.vehicleFootprint` measures the same way once the model is in (`RREventPreviewModels.peek`, new; the spec normalized so the cache key matches; a load that comes back empty is asked again), and until then counts the tiles its Length touches centred on its tile. Tests `event-marker-centre`, `vehicles-starting-position`.
- `Camera.lockReleased` (`reactor_3d.js`) set `scene.menuCalling` as soon as the pointer lock went with `document.hasFocus()` true, so any lock loss read as Escape: in harness runs (focus emulation on a shared display) the menu opened by itself, and a rider's Escape opened the menu since the vehicle never saw a cancel. It now waits 150 ms, drops the release on `blur` or a hidden page, skips it when the page heard Escape itself in the last 500 ms, and presses Escape (`Input.virtualClick('escape')`) so the key's own routing runs (dismount, message, menu). Map data was audited and holds nothing that calls a menu. Runtime **20261024.3**. Test `audit-runtime-3d-camera`.
- `Held.blade` turned the chest with `turnJoint` on top of its last turn. On a Mixamo body the chest it picks (the file's `Spine`) is written only by walk and run clips, and the hold is laid twice a frame (editor paint and `_holdUpdater`; spriteset and room in a battle), so the stance grew every frame until the barrel swung round and the body faced away, and it stayed after the gun was hidden. `Held.stances` records each stance; `unblade` takes it off before the next `aim`/`begin` and, from `HandGrip.update`, when no hold laid it that frame, only where nothing else posed the joint since. `MapHeld.solve` keeps its own slot. Test `held-stance` (synthetic, and Sniper Shot on the Demo's Fleagus at three frame strides).
- `ShaderWarmup.materialReady` counted a never-drawn material as last seen at time 0, so once the page clock passed 250 ms every new material read as "returning to view", compiled a second time and restarted its 5 s timeout. A material whose first compile is pending is not returning. Test `shader-warmup` (clock at 10 minutes).
- `KeyboardNavigation` remembers a dialog whose focus was refused while hidden, and `DetachedWindow` gives it the focus once its window shows, so the Database and Plugin Manager take keys on first opening. Tests `keyboard-navigation`, `detached-window-opening`.
- CI on GitHub (Node 22, committed files only, slower runners): timing budgets measure main-thread CPU time (`tests/helpers/timing.cjs`) and allow 4× under `CI`, reporting between 1× and 4×; the passage stroke times its slices with the frame's clock (`MapEdgeLabels.js`); the thirty-a-side battle runs on a clock that advances between frames; the Sunset import test skips without the project; the interaction-order, issue 54, keyboard-menu and event double-click smokes follow the editor's own windows and the awaited event window in `loadMap`.
