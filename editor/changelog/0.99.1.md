# RPG Reactor 0.99.1 (in development)

Work since 0.99.0. The short version is in the [root changelog](../../changelog/0.99.1.md). Runtime **20261016.5**.

### Changed

- **Levels go to 9999** (`RR_LIMITS.ACTOR_LEVEL`, and the runtime's `maxLevel`, setup and `classParamAtLevel`). Class curves still store 999 levels (`RR_LIMITS.CLASS_CURVE_LEVEL`), or up to the class's target level when it is higher; past the last stored level a curve continues by its last step. The status windows give the level four digits.

- **Defeated enemies stay defeated in battles on the map too,** as Classic placed enemies do: after a battle that was not lost, the enemy rows that fell stay off the map when it is entered again (`Game_Fight.rememberDefeated`). One rule decides for every mode (`F.staysDefeated`): the event's Comes back box, else the enemy's own **Comes back** in Database › Enemies › Shared Combat Settings (`rrBattle.comesBack`, no Note tag), else it stays gone. The event's box shows its enemy's setting and keeps a value of its own only where it differs.

- **Maps with water light at a quarter size** (`Reactor3D.HalfLight`), North Haven included: the unlit twin draws without tint and sheen, the light pass writes a glowing lake's share to a second small target, and the combine adds sheen then tint at each pixel. 3 to 8 ms less GPU a frame on integrated graphics. `Neighbors.mixedWater` and `ShaderWarmup.both` are gone.

- **Arriving on a 3D map no longer stalls.** Rock columns and nearby rock chunks are worked out in the rock workers while the map loads, and the scene is laid over the loading frames (`Reactor3D.Arrival`): pieces a chunk at a time, water, land past the border, foliage, the models asked for, then unseen draws until shaders are ready. Neighbors lay their pieces in parts too. North Haven's worst arrival frame went from 0.58 s to 0.18 s on integrated graphics, inside the black wait, which is about 0.8 s longer (`Arrival.WARM_MS = 0` gives the old wait).

- **Less work per frame:** one walk of the visible scene per pass draw, shared by every reader (`Reactor3D.SceneWalk`); shadow faces hide subtrees with none of their casters (`Shadows.casterOnly`); a refresh with no game update skips the composite unless something changed (`Graphics.skipUnchangedFrames`); the sharpening upscale is drawn in the PIXI composite with no full-size copy (`SharpUpscale.inComposite`, identical pixels).

- **Battle Rooms upload a 2D battler's picture only when it changes.**

- **The editor's 3D view draws animated lights about 20 times a second,** with flicker read from the clock, and media, effects and animated models at most 60 times a second.

- **Even frame pacing on any refresh rate** (`Graphics.FramePacing`): the map is drawn interpolated on frames where updates land unevenly (144, 165, 100, 50 Hz; a 180 Hz screen at 90 fps). `SceneManager.determineRepeatNumber` locks to one update a frame only when the frame is itself a tick long.

- **Less garbage per frame:** glTF arrays repacked and normals computed over the index (three's math no longer boxes numbers), `Reactor3D.IntegerSort`, `Reactor3D.Shadows.sortFaces`, `Reactor3D.DoorRest.enabled`, reused split and depth-first lists; per-frame update walks, gamepad polling, sprite frame clamping and window wheel checks allocate nothing. `Game_CharacterBase.evenShapes` gives each kind of character one object shape, also after a load (`DataManager.evenCharacterShapes` moves every reference to the rebuilt characters; saves unchanged).

- **Arrival and battle start:** a new program's uniforms are read between frames (`ShaderWarmup.readEarly`, `Reactor3D.lazyUniformArrays`); a map's effects load behind the fade (`EffectManager.preloadWithMap`); solved grips are cached (`Reactor3D.GripMemo`); battle line-of-sight hulls are built in a worker with bit-identical output (`ReactorFight.Action.HullWorker`, meshes copied in idle time with `idleCopy`; Tactical AI waits for pending hulls), North Haven's first line of sight 340 ms to 66 ms.

- **2D tilemaps paint in 8x8-tile chunk meshes** built once and moved by the layer, water and waterfall frames advanced by a UV patch (`Tilemap.ChunkPaint.enabled`). Any plugin hook on the paint path keeps the full repaint, which now reuses its quad arrays and uploads only the quads in use; UltraMode7's hooks count as stock while it is not drawing the map, checked against the stock methods (`Tilemap.ChunkPaint.passThrough`). The reason is in `$reactorTilemapStats.chunkFallback`.

- **2D memory and uploads:** the tile atlas packs its sheets to their size and frees its CPU canvas after upload (48 MB to about 19 MB for a full MZ set; `Tilemap.Layer.v8AtlasPacked`, `v8AtlasDropsCanvas`); Bitmap draw ops upload only the area they changed (`Bitmap.partialUploads`); a sprite's neutral colour filter is skipped (`ColorFilter.skipNeutralSpritePasses`).

- **Model textures:** capped at 1024 on the weak tier (`weakTextureSize`), embedded GLB images decoded in the image worker (`GlbCompact`, `ImageWorker.embeddedBytes`), sheets over the cap resampled there (`ShaderWarmup.editorResample`), finger skin weights in a worker, uploads in 4 MB bands. Optional KTX2 copies at import or per model, transcoded to BC7, ETC2 or S3TC in a worker (`Reactor3D.KTX2`, `RRTextureCompressor`). `editor/build-scripts/drop-unsampled-images.cjs` trimmed 13 Demo GLBs from 124.5 to 69.6 MB with no pixel changed.

- **Game manifests and the editor ask for the discrete GPU** with `--force-high-performance-gpu --ignore-gpu-blocklist`, added on create, copy, open and playtest (`"reactorHighPerformanceGpu": false` opts out); WebGL contexts request `high-performance` (`Graphics.gpuPowerPreference`).

- **Editor memory:** `Reactor3D.Shadows.forgetScene` stops every rebuilt 3D scene's models staying in the shadow lists, so `MapEditor3D.SWEEP_MODELS_ON_MAP_CHANGE` is on; the 3D view gives its scene back after a playtest has had the GPU for `PARK_AFTER_MS` (5 s); video effect planes of one file share one video and texture in the 3D view (`SHARE_EFFECT_MEDIA`, Reactor Room 10 decoders to 2) and in the 2D model preview, playing while any of its screens is on view (`ModelPropEffects2D.SHARE_VIDEO`); turning 3D on runs PIXI's collector once at zero idle time, so the 2D map's batches and meshes leave the graphics card (`RELEASE_2D_GRAPHICS`).

- **Reflections cost less on a full-tier GPU.** A water mirror draws only the part of its picture that water at its level can show on screen, at the same pixels, its eye narrowed to that part so the rest is culled; a lookup outside it keeps the capture (`Reactor3D.Mirrors.WATER_AREA`, `rrMirrorArea`). The capture's face for an update is drawn on the next refresh with no update, or with the next update when none comes (`Reactor3D.Reflections.SPARE_REFRESH`, `Graphics.refreshCount`). North Haven on an i5 laptop with an RTX 3060 at 144 Hz: 816 to 615 draw calls a frame, frame p95 20.8 to 14.0 ms.

- **Pieces and plants are drawn a region at a time** (`Reactor3D.DrawBatches`): still laid and edited a 16-cell chunk at a time, they are drawn as one mesh per material per 64-cell region, the chunks' arrays copied end to end and the chunks kept hidden for picks, ghosts, mirrors and edits. A region is made again from the arrays when a chunk under it comes or goes, before the next frame (`flush`, from `prepareWorldFrame` and the editor's `renderFrame`). Plants keep their instances in order of their thinning share. A finish, a textured see-through material and an animated part keep their own draws; glass merges. The region's own arrays are let go of once uploaded (`FREE_ARRAYS`) and remade from the chunks after a lost context. North Haven at 144 Hz on an i5 laptop with an RTX 3060: 639 to 298 draw calls a frame, identical pixels on four maps.

- **The quarter-size light is drawn on integrated GPUs only** (`Reactor3D.HalfLight.WEAK_ONLY`): a discrete GPU lights each pixel in one draw, which costs it less than the split's second walk and draw cost the CPU. North Haven's frame median went from 13.8 to 6.9 ms on the RTX 3060 laptop.

- **The static light volume moves in 8-tile steps** (`Reactor3D.LightVolume.REGION_STEP`): it was laid again for every tile the player walked, making three new 8 MB targets each time, and now reuses a retired volume's targets. A 5 s walk through North Haven: 283 to 48 bake steps.

- **Hidden and closed windows are not laid out every frame** under PIXI v8 (`Window.SKIP_UNSEEN_LAYOUT`).

- **The editor's 3D view sets the world matrices once a frame before the shadow rows and the reflections,** and while the view moves the capture takes a face every other draw (`MapEditor3D.PROBE_HALF_WHILE_MOVING`); a frame after one that showed nothing shiny takes none. Orbiting North Haven: 14.4 to 9.75 ms a draw.

- **Perf tools:** `nw-game-profile.cjs` reports boot and map arrival times; both NW perf tools take `--profile-dir`; a frozen-frame variant in `nw-frame-breakdown.cjs` can ask for more warm-up frames (`warmFrames`) when its programs compile afresh. A render-in-a-worker prototype is in `editor/tests/perf/render-thread/` (loaded by nothing).

- **User Interfaces: an Angle turns a node about its center.** Box, Image, Text, Button, Gauge and Text Input nodes take `angle` (degrees, -180 to 180, saved only when not 0; `ReactorUI.TURNABLE_TYPES`), so a button laid over a slanted tab is highlighted and clicked along the tab. The game turns the node's window about its center (`syncVisualState`, `_uiTurnX`/`_uiTurnY`) and its hit test follows the turn; the editor canvas draws, picks and resizes the node in its own frame (`turnContext`, `localPoint`, `resizeTurned`, which keeps the opposite handle in place).

- **The event editor opens in a window of its own** (requested on GitHub; the owner's design): in the desktop editor every event opens in a frameless, transparent window with the editor's rounded corners and the accent strip on its title bar, that can sit anywhere, a second monitor included, its own header dragging it, its × closing it and a corner grip sizing it; dropdowns there are themed and open inside it (`SelectThemingShim` watches its document and places a list by the window it opens in) (`EventEditorWindow.js`, `event-editor-panel.html`). It keeps its place between events and sessions, back over the editor when its screen is gone (`nw.Screen`), and stays in front of the editor while Reactor is the app in use (`setAlwaysOnTop` follows both windows' focus). The map stays live: double-clicking another event swaps it in place (`EventEditor.leaveEvent`), asking Apply, Discard Changes or Cancel first when edits are unapplied (`hasUncommittedChanges`, `resolvePendingChanges`); a map change closes it the same way (`closeForMapChange`); the open event dragged on the map shows its new place, deleted, the window closes; copy, cut, paste and Delete follow the last click or Tab (`UIManager.eventEditorHasKeys`). The editor and every dialog it opens work there unchanged through `PopoutBridge.js` (the main document's lookups, input listeners, focused element and new dialogs reach the window while it is worked in). While its window is open, its event stays outlined on the map in event and tile mode alike (`EventManager.updateEditingHighlight`). The map hears only its own window: library listeners (PIXI's pointer tracking, three's controls) are not relayed to the editor's, so its tile cursor no longer follows the mouse there and clicks there no longer reach the map. The event's picture keeps its proportions in the preview, drawn again for its box when the window is resized (`object-fit: contain`, `EventPageEditor._redrawOnResize`). The web editor, which cannot open windows, floats it inside the page instead, dragged by its header, sized from its corner, its place remembered. New, Open and Playtest still wait for it to close.

### Fixed

- **The 3D map view draws model effects on their anchor again.** Since the view moved to a reduced render scale, an effect quad was sized to the canvas instead of the main pass target (`MapEditor3D._placeEffectQuad`), so the reactor core's energy beam stood off to the side, in every project.
- **Looping model effects repeat with no blank frame.** The editor gives a restarted play one update before drawing it and falls back to the play's own length when its lit frames were never measured (`AnimationPreviewLayer`); the game restarts a loop just before the play ends (`reactor_3d_effects.js`). The lit-frame check runs on the first frame at or past each multiple of ten, so frames that run several updates at once no longer skip it, and a last lit frame counts as the end only once a later check found the effect dark: on the separate-canvas fallback a missed check had cut plays short (Core (2) restarted every 0.3 s).
- **Shadows drawn during the quarter-size light pass include characters and props again** (`HalfLight.whole`), and a glowing lake's halo no longer stops at reeds.
- **The light no longer changes shade at a border between a map with water and one without.**
- **Battle Room battlers no longer make and leak a texture each update.**
- **Battles on the map no longer check 10,000 empty event slots** each time they ask whether an event is starting (`F.anyEventStarting`), 2 to 3 ms a battle frame.
- **Reactor UI windows are built through the upgraded window classes** (`built()` in `reactor_ui.js`), no longer taking the slow copy path at an Action battle start.
- **Model normals are computed after the index is read,** so the Black Hole animation model is lit correctly.
- **`MapEditor3D.releaseEffectPlane` is safe to call twice** and never frees a video another plane still shows.
- **Effects that time out while preloading are released when they arrive,** and a load that fails at once no longer holds the scene for 8 s.
- **Camera transitions take the frames they are given.** The map camera was aimed twice per update, so a 60-frame Change Camera took 30 and ran unevenly on catch-up updates. The turn ease (`TURN_RATE`) went from 0.18 to 0.33 to keep the same feel.
- **A battle kept on another map no longer blocks battles elsewhere.** Start Battle on Map, random encounters and the battle screen asked whether any battle was running instead of one on this map. The kept battle now ends as an escape when another starts (`Game_Fight.endKept`); its units, music, followers and Tactical camera are left alone on the map the party is on, and its outcome waits for the party's return.
- **A party member added during a battle on the map joins it** (`Game_Fight.takeNewMembers`, after Change Party Member and Formation), on a free cell beside the leader; one who left and came back keeps their unit.
- **Action and First Person battles that can be escaped are escaped by running.** Once an enemy has come within `A.ESCAPE_DISTANCE` (15 tiles), the leader further than that from every enemy for `A.ESCAPE_FRAMES` (90) ends the battle with the escape message and the Escape branch (`A.updateGetaway`). `$gameFight.commandRetreat()` does the same from a script.
- **Enemies placed on a Classic map stay defeated** after the battle, across map visits and saves, unless their In battle row says Comes back (`Game_Fight.setEventDefeated`, `eraseDefeated`).
- **A vehicle sliding along a closed map edge no longer leaves by the next border early.** A refusal at the border now leaves only by the border that refused (`pastSide` in `reactor_vehicles_drive.js`).
- **Copy Page and Paste Page in the Event Editor carry the page's 3D model.**
- **Editing an event on a 2D map no longer leaves an empty 3D sidecar,** so the map no longer reads as changed after Undo.
- **A damaged project lock no longer stops a project opening.** A lock that cannot be read and has not changed for 10 seconds is treated as stale.
- **Database › Tilesets:** the list row shows a new name as it is typed.
- **User Interfaces:** the Inspector drawer starts below the Layout toolbar instead of covering it, and its close button shows.
- **Database › Types:** below 980 px the five lists share two rows instead of scrolling sideways.
- **Database › Terms:** command fields go to three columns at 1300 px and two at 900 px, so values like `\i[604] EQUIPMENT` show in full.
- **Build › Door and Window frame:** a setting's field takes the rest of the row, so the Opens choice shows in full.
- **Import Project:** settings sit on one label and field grid and the log takes the height left, so the dialog fits 1366×768 without scrolling.
- **`nw-map-tool-switching.cjs`** follows the Models group's move to the Build bar.
- **A replaced title no longer skips a pre-title splash plugin.** The router installed over plugins swapped `Scene_Title` for `Scene_ReactorUI` before they saw it, so Ramza_PreTitleSplash_MZ never played. The swap now happens in the router next to the engine's `goto` (`ReactorUI.sceneRouter`, `engine`), after every plugin around `goto` and `push` has seen the stock class; a router over plugins swaps a stock scene left queued by a plugin that replaced `goto` outright.
- **Item, Status, Skills and Equip buttons work in an interface with no party panel.** A button set to Select Actor first only buzzed when there was no party list to pick in (AbyssGazes' journal menu); it now acts for the menu actor, as with Select Actor off (`beginActorSelection`). Formation and choosing an item's target still need a panel.
- **Escape in a Database dialog closes that dialog only.** Class Learning, EXP Curve and Generate Curve, Enemy Action, Troop Conditions, Command Window Settings and the Title image picker never took focus or their Escape, so the key reached the Database window behind them, which closed or asked to discard every edit (the EXP Curve one did nothing). Each takes focus as it opens and gives it back to the button that opened it.
- **Skill Type offers None** (`DatabaseSkillEditor.skillTypeOptions`), so Attack and Guard, stored as type 0, no longer show "Magic", and a skill whose type has no name keeps its own entry.
- **3D view: a building double-clicked in Build › Select drags at once.** The double-click selected the view's hint text, and the next drag began a native text drag that cancelled the pointer; the input surface and the hint select no text (`MapEditor3D.INPUT_SURFACE_CSS`).
- **A selection's Materials list shows each part's count apart from its name** ("Wall 48", not "Wall48"), the picked part highlighted: the `.rr-build-part*` classes had no rules.
- **Battle Processing has its result branches.** Ticking Can Escape or Can Lose added no If Win / If Escape / If Lose rows, and nothing else adds them, so nothing could run only on a win, an escape or a loss (the command went through the one-command table). `BattleProcessingEditor.block` now writes them; editing keeps each branch's commands and asks before removing one that holds commands, as Start Battle on Map does.
- **Text code descriptions use US spelling** (color), with their Chinese translations rekeyed.
- **A gun is never aimed behind the back.** An aimed arm reached straight for its target, so a unit aiming before it had turned to the target (or facing away from it on a ride) held its rifle behind its back, the arm twisted and the barrel through its body: Carol's railgun in North Haven's Tactical battles. The aim now stops at the edge of the body's front arc, 70 degrees either side of where the shoulders face (`Reactor3D.Held.frontGoal`, `AIM_ARC`), for map units and Battle Rooms alike.
- **Walking outside, buildings are no longer seen through.** The see-through corridor through walls between the camera and the party (and the nearest events) opened inside a building or out; it now opens only while the player is under a roof, or in a battle on the map (`updateCutaway`). On North Haven a strip of the house wall was cut open around an NPC inside while the player stood outside.
- **Followers are never thinned or cut part-way in 3D.** A placed model in the sight line from the camera to the player fades with a dither, and characters' own models were spared only in a battle, so a follower trailing behind the player lost parts of itself and showed the inside of its model. Characters (the party, followers, NPCs) are marked as bodies on every map from the first frame (`cutawayMarkBodies`) and the shaders pass a body by, battle or not; scenery still thins.
- **"Whole Map" encounters happen on region tiles too.** Map Properties stored the whole map as region 0 (`regionSet: [0]`), which the game reads as "region 0 only", so a region tile offered only its region troops. The editor now writes `[]`, and `Game_Player.meetsEncounterConditions` reads a lone 0 as the whole map, so maps saved earlier play right without a save (region IDs run 1 to 255).
- **Paste Map from a map's right-click menu puts the copy right after that map,** and from the empty part of the Map Tree at the end of the top level (`pasteMap(afterMapId)`); Ctrl+V still pastes after the open map.
- **Event Editor: Ctrl+C on a selected command copies the command.** The map's event copy took the key even with the Event Editor open, so Ctrl+V after it added nothing (`UIManager`).
- **The event command list's right-click menu stays inside the window,** so a row near the bottom still reaches Paste and Delete (`EventCommandList.keepMenuOnScreen`).
- **A new Set Movement Route command runs once and waits:** Repeat Movements off, Wait for Completion on (`SetMovementRouteEditor.newCommandRoute`); a two-step player route had walked forever. A page's autonomous route still repeats.
- **Control Timer's "(m:ss)" follows the seconds as they are typed** (`ControlTimerEditor.durationLabel`).
- **Picture meters and digits whose art is missing fall back to drawn ones.** A file that failed to load called no load listener, so a part waiting on it never redrew (a full HP bar stayed empty), and a missing file's blank stand-in (`_degradedToBlank`) counted as art. `ReactorUI.whenReady` now also watches for the failure and `softFailed` treats the stand-in as missing; the baseline Battle HUD in a project without `img/system/BattleHud_*` shows its HP, MP and TP bars.
- **Stock layouts name the screen they were laid out for** (`design` on every record `StockInterfaces.build`/`buildOne` makes), so a project that changes its resolution afterwards has them fitted to the new screen. AbyssGazes' baselines, made at 1280x720 before the project went to 1920x1080, stood in the top-left two thirds of the screen.
- **A record with its own Close button gets no touch Back button over it** (`Scene_ReactorUI.needsCancelButton`): the baselines' Cancel button sat under the stock one at the top right.
- **Database › System 1:** checkboxes beside a long label no longer shrink to a sliver (`.system-checkbox` keeps its size).
- **UI smokes:** `nw-user-interface-layout.cjs` skips toolbar children that are not drawn, and `nw-user-interface-interaction.cjs` checks a Formation swap against a party of any size.
- **User Interfaces says when the game does not use a record yet.** A record laid out as a stock screen that no record replaces shows "The game still shows its own …" under the toolbar with a **Use as** button that binds it (`unboundStockRole`). The baseline notes for Title and Victory named System 1 and System 2, which bind nothing; they and the guide now name Use As.

- **Script commands show every line in the event, troop and common event lists,** each continuation line as its own row (code 655), instead of the first line and "(+N more lines)". A click on any line selects the whole Script, and a double-click opens it; in a troop's list a double-click on a later line now opens the Script too.

- **Show Text and Comment lines are readable in light themes.** A line's normal text was drawn in the window skin's color 0 (white in the stock skin) on the light rows, visible only while selected. Light themes set `--rr-message-normal-color` to the list's text color, and `\C[n]` colors there carry a dark outline as the game draws them; dark themes are unchanged (`EventCommandList.convertTextCodesToHTML`, `styles.css`).

- **A new blank project's window skin is laid out as the engine reads it** (`ProjectManager.writeStarterWindowSkin`): the 32 text colors, a cursor, scroll arrows and a pause sign, where a solid square drew black text with no cursor.

- **A new blank project names every menu and battle message** (`ProjectManager.STARTER_MESSAGES`, the 53 standard terms): Options rows, save slots and battle and level-up messages were empty.

- **Windows builds embed the project's icon in Game.exe.** An icon over 256 px a side is scaled to 256 for the ICO entry, and smaller again if the exe's icon slot needs it (`icon-helpers.js` `shrinkPng`, `embedExeIcon`).

- **A copy of an open project folder opens.** The project lock records its project's real folder (`ProjectController._projectLockFolder`), and a lock that names another folder came along with a copy; the original stays locked. Locks written by older editors cannot tell.

- **The 2D map view draws vehicles as the 3D view and the game do.** A vehicle event whose page shows no picture draws its vehicle's model (`EventManager.previewModelRaw`), and every vehicle, events and Starting Positions, stands at its heading along the model's front (`ModelPropsPreview2D` poses it with `Reactor3D.Vehicles.pose`); changing Heading redraws it at once.

- **Quest Reward command: a reward with no text of its own is listed by what it gives** (250 G, Potion ×2, 30 EXP, Common event: name) instead of a blank line (`QuestCommandEditor.rewardLabel`).

- **The quest log's windows reach the bottom of the screen.** `Scene_Quest` kept the space for a help window it never shows; its help area is now 0 (`reactor_quests.js`, runtime 20261016.1).

- **Plugin Manager: turning a plugin off by its checkbox dims its name right away,** the same as when the list is drawn (`PluginManager.createPluginListItem`).

- **Tactical battles: Attack and Dismount stay grayed in a unit's menu after a skill or item target is cancelled back to the list.** The menu is listed again while the stage is still the list, and `Game_Fight.commandReason` answered only on the command stage, so it showed Attack as available with nobody in reach (`reactor_fight_tactical.js`, runtime 20261016.2).

- **Character Generator: the Layers list shows only the parts the preview draws and Save writes.** After a style or gender switch it still listed the other style's parts; they now stay in the order and come back when that style does, and Up/Down move a layer past its listed neighbor (`CharacterGenerator.js`).

- **Database: Delete after clicking a preview (such as an animation cell) no longer clears the whole record.** A preview canvas takes no focus, so the key reached the record list's Delete shortcut; keys after a click inside the detail pane stay with the detail (`DatabaseEditorUI._keyFollowsDetailClick`).

- **Animations: a new Effekseer entry no longer logs an error** before an effect file is chosen.

- **Deployed, encrypted MV games boot.** Savior & Religion stayed on a black screen; four causes, each fixed (runtime 20261016.3):
  - Install Reactor Runtime took a deployed MV game (no `Game.rpgproject`) for MZ and stamped `$reactorMvCompat = false`, turning every MV game rule off. The engine is now read from the corescript before it is archived (`ProjectManager.isRpgMakerMvProject`: `js/rpg_core.js` is MV, `rmmz_core.js` MZ), and opening a project converted that way switches it to MV when its backup zip holds MV's corescript (`repairMvCompatFlag`).
